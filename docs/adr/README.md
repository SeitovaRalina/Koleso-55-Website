# Architecture decision records

ADRs record only decisions whose reversal changes architecture, security,
operations, API contracts or durable product behaviour.

Format: `NNNN-short-title.md`. Keep records immutable. If decision changes,
mark old ADR `superseded` and link replacement; do not rewrite history.

Each ADR states: status, date, context, alternatives, decision, consequences
and evidence. Do not create ADR for ordinary bug fixes or implementation notes.
